## 2. 论文构造：逐字复现（精确）

参考实现 `construct_cc_10_7_134753.py` 的结构是 `B × B` 加两圈条带：

```
B = R367 \ {r_j}                     |B| = 359
X = tr(R367)，下标 267 改为 (1,5,6,3,5)
J0 = {0,5,6}，J1 = {1,2,3,4,7}
A = {x ∈ X : x 与 PV 中某点相邻}
D = {x ∈ X : x 与 PH 中某点相邻}
规模 = |B|² + 2·d·|X| = 134,689 + d²   → d=8 时 134,753
```

`src/scnet/p004/paper_construct.py` 的结果：

```

```

**关键细节**：`J1` 必须含 pair 7。漏掉时大小仍是 134,753，但不是独立集
（对称差 340 点），`is_valid` 会报错。本轮早期一次 176 点偏差就源于此。

## 3. 为什么这一族封顶在 8 对（精确，限该族）

私有对端点必须落在自由区 `V' = D ∪ pool(D)`。`|D|=8` 时 `|pool(D)|=8`
（恰好 8 个 `q_j`），`|V'|=16`，其诱导图 16 顶点 11 边，`α(V')=8`。
所以这一族最多 8 对；134,753 是它的上限。

另一条路：若 `α(C7⁵) ≥ 368`，则 `368² = 135,424`，直接破纪录。论文作者
“不相信 367 能提高”，但**没有证明**；本轮没有新计算。

## 4. 交换搜索：审计史（重要）

旧目录的 `quad45.c / tri45b.c / five6.c / five6b.c / pair5.c` 有五处真实缺陷：

1. 15 位键打包溢出；
2. C 负数取模导致 `d−1` 邻接错误；
3. 候选索引“对键写入、单键查询”错配；
4. 容器容量静默截断，却仍报“完成”；
5. P5 / K1,4 分类覆盖缺口。

**旧结论“k ≤ 5 完备”已作废。** 旧程序打印的 m1/m2/m3（5,178 / 144,861 / 999,144）
后来被新程序复现，说明数字本身对，但当时的“完备”没有依据。

新程序 `sixm3.c`（C++17，OpenMP）：

- 显式 5 字段键、动态容器、无截断；
- 剪枝只用一条组合事实：最小改进交换的 blocker 超图连通（否则有更小改进）；
- 枚举自然 rank-k 边、rank-(k−1)+一个连通扩展、k=5 的 rank-3+一/两个扩展、
  以及所有连通配对图集合；
- 输出 `complete=1` / `UNKNOWN`（节点上限）/ `INCOMPLETE`（超时）。

自检与覆盖交叉验证：49 个坐标情形、1,000 个随机图 × 6 个目标、100 次强制哈希碰撞、
100,000 对 mask-谓词；3,072 个 graph/size 组合与 5,002 个超图 × 25,010 组合和暴力一致。
