## 2. p004：问题与编码

C7<sup>⊠10</sup> 的顶点是 10 位 base-7 字符串。两个点相邻，当且仅当**每个坐标**
的差都在 {0, ±1} mod 7 内（`x ≠ y`）。独立集就是“任意两点至少一个坐标相差 ≥2”。

- 前缀 `p` = 前 5 位，后缀 `s` = 后 5 位，均编码为 0…16,806。
- 一个点的闭邻域 = 243 个前缀 × 243 个后缀（前缀、后缀各自独立取邻域）。
- 独立集的判定因此可以按前缀分块：同一前缀内后缀两两不相邻，不同前缀 `p,q`
  只有 `q ∈ N(p)` 时才需要比较后缀。

基线：`problems/p004-shannon-capacity-c7/baseline`，134,753 点，本轮复算

```
{"valid":true,"score":"134753","canonical_hash":"650b0556…","message":"ok"}
```

## 3. 论文构造的逐字复现（精确）

论文/参考实现：`lbs-repo2/c7/construct_cc_10_7_134753.py`。结构是

```
C = B × B  ∪  {(x, r_j) : x ∈ A, j ∈ J0}  ∪  {(q_j, x) : x ∈ D, j ∈ J0}
           ∪  {(x, q_j) : x ∈ D, j ∈ J1}  ∪  {(r_j, x) : x ∈ A, j ∈ J1}
```

其中

- `R` = 367 点 F₇⁵ 独立集（`R367.txt`）；
- 8 个“私有对” `(r_j, q_j)`，`r_j ∈ R`，`q_j ∉ R` 且 `q_j` 在 R 中的唯一邻点是 `r_j`；
- `B = R \ {r_j}`，`|B| = 359`；
- `X = tr(R)`，`tr(w) = ((2−w₁), w₃, w₀, (2−w₂), w₄)`，再把下标 267 的点替换为 `(1,5,6,3,5)`；
- `J0 = {0,5,6}`，`J1 = {1,2,3,4,7}`；
- `A` = 与 `PV` 中某点相邻的 X 点，`D` = 与 `PH` 中某点相邻的 X 点。

规模 `|B|² + 2·d·|X| = 134,689 + d²`；d=8 时 **134,753**。

本轮结果（`src/scnet/p004/paper_construct.py`）：

```
SIZE 134753 B 359 A 20 D 26
OFFICIAL_VERIFY {"valid":true,"score":"134753","canonical_hash":"650b0556…"}
COMPARE {"reference":134753,"mine":134753,"only_reference":0,"only_mine":0}
```

**J0 为什么是 {0,5,6}**（`src/scnet/p004/j0_scan2.py`）：8 个私有对里选 3 个放 J0 共 56 种，
逐一按同一公式造集并检查，**只有 {0,5,6} 给出独立集**（134,753 点），其余 55 种都在
`cross p=… q=…` 一类冲突处失败。J0 不是随手挑的。

**踩过的坑**：`J1` 必须包含 pair 7。漏掉时集合大小仍是 134,753，但不是独立集，
与正确集合的对称差是 340 点（170/170）；官方 verifier 直接拒绝。本轮早期曾因此
出现一次 176 点的偏差记录，现已由 `is_valid` 自检和 `--compare` 兜住。

## 4. 结构：为什么这一族封顶在 8 对（精确，限该族）

私有对的两个端点必须落在“自由区” `V' = D ∪ pool(D)` 内，才不会与 `B × B` 冲突：

- `|D| = 8` 时 `|pool(D)| = 8`，恰好是 8 个 `q_j`，所以 `|V'| = 16`；
- `V'` 的诱导图有 16 个顶点、11 条边，`α(V') = 8`；
- 因此这一族最多 8 对，134,753 就是它的上限。

换一条路：若 `α(C7⁵) ≥ 368`，则 `368² = 135,424` 直接超过纪录。论文正文说作者
“广泛尝试后不相信 367 能提高”，但**这不是证明**。本轮没有对 `α(C7⁵)` 做新的
精确计算，所以这一条保持“未知”。

`|D| = 9, s = 9` 时规模是 `358² + 18·367 = 134,770`，理论上留出 16 个空位。
但要凑出 9 对，需要一个 9 点的独立自由区（`|pool(D9)| ≥ 9`）；本轮**没有找到**
这样的 D9。这一方向属于未完成，不是否证。

## 5. 交换搜索：先审计，再重算（精确，限两个点集）

### 5.1 旧程序的问题（已作废）

旧目录的 `quad45.c / tri45b.c / five6.c / five6b.c / pair5.c` 至少有五处真实缺陷：

1. 15 位键打包溢出（前缀/后缀拼进一个整数时越界）；
2. C 的负数取模：邻接判定在 `d−1` 处得到负值，未归一化；
3. 候选索引由“对键”写入、却按“单点键”查询，命中率错误；
4. 容器容量静默截断，超出部分被丢弃但程序仍报“完成”；
5. P5 / K1,4 分类存在覆盖缺口，部分连通结构从未被枚举。

**因此旧的“k ≤ 5 已完备”结论全部撤回。** 旧程序给出的 m1/m2/m3 计数
（5,178 / 144,861 / 999,144）后来被新程序复现，说明那三个数字本身没错，
但当时的“完备”声明没有依据。

### 5.2 新程序 `sixm3.c`

- C++17，显式 5 字段键（无打包），动态容器，无静默截断；
- 只用一条组合事实剪枝：**最小改进交换的 blocker 超图是连通的**，否则某个连通
  分量本身就是更小的改进；
- 枚举：自然 rank-k 边、rank-(k−1) 边 + 一个连通扩展、k=5 时 rank-3 边 +
  一/两个连通扩展、以及**所有**连通配对图集合（不只是路径和星）；
- 输出三态：`complete=1`（完备）、`UNKNOWN`（节点上限）、`INCOMPLETE`（超时）。

自检（本轮本机串行复跑）：

```

MASK_SELFTEST random_pairs=100000 PASS baseline=134753
```

覆盖交叉验证：3,072 个 graph/size 组合、5,002 个超图 × 25,010 组合，与暴力枚举一致；
8/8 个快照池用官方 verifier 重建一致；12 个更大的三元池确认不含独立 4-集。

## 7. 九对族：从 50 个候选到“只差 1 个空位”

### 7.2 固定 X 的严格 2-SAT（精确，限 50 个模型）

### 7.4 允许删槽的 CP-SAT（精确/未判定）

对 50 个候选、X0、阈值 134,754（即允许 ≤16 个空位）：**49 个 INFEASIBLE + 1 个
UNKNOWN**。那 1 个未判定不能用来说明任何方向的结论。

### 7.5 权重化删点优化（精确，六个固定模型）

把“最少删几个槽位”作为目标直接求解（`frontier9.py`，全部 `OPTIMAL`）：

| 变体 | X | 最少删点 | 规模 | 距 134,754 |
| --- | --- | ---: | ---: | --- |
| R2 | `tr(R)+patch` | **17** | 134,753 | **差 1** |
| R1 | `patch` | 18 | 134,752 | 差 2 |
| R1 | `tr(R)` | 18 | 134,752 | 差 2 |

**这就是“差 1 个空位”的确切含义**：不是启发式差一点，而是在这六个固定模型上

## 9. p005：负结果的完整链条

基线复算：`{"valid":true,"score":"512","canonical_hash":"f76ee04c…"}`；
512 点互异；**0 个可加点**；三层切片（按 x₀）为 **192 / 160 / 160**。
集外每个点的冲突数最小为 **4**（`analyze.py`：冲突数 ≤2 的点为 0 个），所以插入任何
集外点都要先删至少 4 个基线点，净收益为负。

| 尝试 | 结果 | 强度 |
| --- | --- | --- |
| 集外点插入代价（`analyze.py` + `transversals.py`） | 每点冲突 ≥4；冲突数 = 4 的 16 点其 4 对互不相交 ⇒ 至少删 4 点 | 精确 |
| 结构化删点（`r10.c`，KK=10：逐点取 10 对，枚举 2¹⁰ 种删法） | 最多回填 2 点（x=2472，净 −8） | 精确，限该族；日志 `logs/scnet/p005/rk13.log` |
| KK = 11/12/13（`rk.c`/`rk12.c`/`rk13.c`） | 代码在，本轮无运行日志 | 未判定 |
| 增长式构造（`grow2.c`） | 最好 328 | 启发式 |
| 640 核 600 种子最小冲突 | 最好 E=7，无 E=0 | 启发式（远端记录） |
| 全局 K=513 CP-SAT | 本地 + 远端 2×2 小时均 `UNKNOWN` | 未判定 |
| 固定单层 f=0/1/2、随机 ℓ 层子问题 | `UNKNOWN` | 未判定 |
| 3 个完整模型 | 240 GiB cgroup 下 OOM | 未判定 |
| 乘积路线（需 112 点 F₃⁶ 帽集） | 本地搜索只到 85 | 搜索失败，不是不存在 |

**勘误（同日）**：本报告早期版本写过“r ≤ 13 的删点-回填被穷举，最多回填 2 点”，
把 `rk13.c` 当成了“r=13 的完全枚举”。复核源码后确认它的真实语义是：对每个集外点
取 **KK 个互不相交**的冲突对，枚举“各删一端”的 2^KK 种删法再统计全局可加点数——
不是所有 r ≤ 13 的组合。只有 KK=10 的日志被保留。原强结论撤回，替换为上表版本。

注意最后一行：α(F₃⁶)=112 是已知可达的，本地只搜到 85 说明子搜索太弱。
把它写成“乘积路线被排除”会是错误的。

p005 的正确结论：**512 仍是最好的可验证值；513 需要与基线无关的新构造。**

## 11. 这一轮的方法教训

1. **先审计实现，再相信“完备”。** 旧 C 程序的五个缺陷里，任何一个都足以让
   “无解”变成假结论；真正危险的是它们都仍然打印“完成”。
2. **区分 `UNKNOWN` 与 `UNSAT`。** CP-SAT 的 `FEASIBLE 512` 只说明找到一个 512，
   不说明 513 不行；`INFEASIBLE` 才是否证，而且要写明输入。
3. **建模要覆盖退化情形。** 2-SAT 模型最初漏了“同一点、同一对、同一端点”的
   HV 冲突（`x+a` 与 `a+x` 在 `x~a` 时冲突），结果 8 对的控制组给出了非法集合。
   修好后必须让控制组重新产出 134,753 才能继续。
4. **压缩必须保持权重。** 等签名点合并后，按“变量个数”限制删点会错；要么用
   未压缩模型，要么用多重权重。否则“最优 17”可能只是压缩假象。
5. **一个数字要能被独立重建。** 三个归档点集都能用 verifier 复算、且哈希互不相同，
   这样“134,753 有很多个”才是可核查的事实，而不是叙述。
